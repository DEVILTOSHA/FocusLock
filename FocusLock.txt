  Live test, with Notepad and a 1-minute budget:
  - Countdown: the timer ran down, the card turned amber and showed "Almost up"
    near the end, and the stats updated.
  - Lock: at zero, the overlay covered Notepad's window exactly, stayed above

  What's in it:
  - CMakeLists.txt: C++20 and Qt 6 Widgets. After each build it copies the Qt
    DLLs next to the exe, so you can double-click build\FocusLock.exe.
  - ProcessMonitor: a background thread that checks running processes once a
    second with CreateToolhelp32Snapshot and counts down the timers.
  - WinUtil: finds each app's main window with EnumWindows and gets its position
    with GetWindowRect, plus a few other Windows helpers.
  - OverlayDialog: the frameless, always-on-top lock screen. It follows the
    target window as it moves, and Esc and Alt+F4 don't close it.
  - MainWindow, WatchCard, Theme.h: the dark Rize-style UI. It has stat tiles,
    one card per app with a live countdown and −/+ buttons for the time limit, a
    tray icon, and a saved watchlist.

  Choices I made that the spec didn't cover:
  - Timer only runs while the app has a window open. Apps hidden in the tray
    don't use up their time.
  - The lock also lifts when the app's last window closes, not only when its
    process ends. Otherwise apps like Discord would stay locked forever while
    sitting in the tray.

  end too.

  Clock-independent cooldown: FocusLock will keep its own time counter that
  never reads the system clock.
  - While Windows is running: the counter advances with GetTickCount64. That's
    the time since boot; it includes sleep and ignores clock changes.
  - Across reboots: off time can't be measured locally, so the counter takes the
    true time from the Date header of HTTPS servers (Google, Cloudflare,
    Microsoft) and credits the gap. If it can't reach them, it credits nothing,
    so you can't skip time.

● Both loopholes are closed, and the build has no warnings.

  Limit lock: once an app starts using its budget, its limit can't be raised or
  lowered until the budget refills. The −, + and minutes field are greyed out,
  and the card says "Refills in 24 h · limit locked until then". Before first
  use you can still change the limit freely. I also disabled the ✕ remove button
  during that time, because removing and re-adding the app would have reset it
  to a new 30-minute limit. Even if an app gets re-added, FocusLock restores the
  frozen limit it saved.

  Clock-proof cooldown: the 24-hour cooldown no longer reads the system clock.
  The new src/TrustedClock.* keeps its own count of time:
  - While Windows is running: it uses GetTickCount64, the time since boot. It
    includes sleep, and changing the Windows clock has no effect on it.
  - After a reboot: the time the PC was off can't be measured locally. FocusLock
    checks the real time against Google, Cloudflare or Microsoft and credits
    the gap. With no network it credits nothing, so the cooldown can only run
    slow, never fast. This means FocusLock now sends a small request to one of
    those sites every 30 minutes.

  - Frozen controls: the controls greyed out and the remove button was disabled

  - Network sync: it succeeded within a second of launch.
